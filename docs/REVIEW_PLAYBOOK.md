# 个股复核操作手册（方案A）

目的：在程序公式排出的次日买入顺延链上，补上公式看不到的信息（公告、新闻、板块、资金），否决明显有雷或逻辑不成立的股票。复核本身也要接受检验：每周进化报告会比较“复核后买的”和“公式本来会买的”5 日收益，满 20 次仍未跑赢就取消复核。

## 1. 读输入（服务器本地文件，只读）
- 每组：`/opt/qishi-arena/studios/<A-E>/ledger.json` → `pending_buy`（顺延链，最多 5 只，含 code、name、signal_close、max_buy、type 自主/强制、layer 新批/老池、score）、`review.status`。
- 全池评分：`/opt/qishi-arena/reports/scores/<日期>_<组>.csv`。
- 组规则：`studios/<组>/STUDIO.md`、`genome.json`。
- 只复核 `review.status == "待复核"` 的组。顺延链为空的组跳过。

## 2. 每只要查的内容（查不到就写“未查到”，不要猜）
1. **公告（最近 10 个交易日 + 未来 10 日已知事件）**：减持/解禁、问询函/监管函/立案、业绩预告或快报、重大合同、停复牌、股权质押平仓风险。来源优先交易所公告（上交所 sse.com.cn、深交所 szse.cn、巨潮 cninfo.com.cn）。
2. **新闻与题材**：上涨原因是否有可验证的事实；题材是否是当前主线；是否已经被证伪或兑现。
3. **板块**：所属板块当日和 5 日强弱；同板块龙头当日是否炸板或大跌。
4. **资金**：龙虎榜（机构席位还是一日游游资）。
5. **K 线位置**：距 250 日高点、距 120 日低点、近 5 日涨幅；是否连续加速后的高位；成交额是否足以按 10% 仓位成交。
6. **是否符合本组定位**：例如 C 组是“低位吸筹”，却在链里出现已大涨的票，应说明。

## 3. 否决标准（满足任一条即否决，理由写具体事实）
- 未来 10 个交易日内有大额解禁或已公告的减持计划正在执行。
- 有未回复的问询函/监管函、立案调查，或业绩预告大幅下修。
- 上涨唯一理由是传闻且已被公司澄清。
- 板块龙头当日跌停或炸板，且该股是跟风补涨。
- 近 5 日涨幅 > 30% 且当日放量收长上影（高位出货特征）。

不满足否决条件的，一律“同意”。**不要因为“感觉一般”否决**；可以通过重排顺序表达偏好，但重排也要写理由。

## 4. 写回
在服务器本机执行（口令从 /etc/qishi.env 读取，不要写进任何文件）：
```bash
set -a; . /etc/qishi.env; set +a
curl -s -X POST "http://127.0.0.1:${QISHI_PORT:-8711}/api/review" \
  -H 'Content-Type: application/json' -d @- <<EOF
{"token":"$QISHI_TOKEN","studio":"E","summary":"一句话总结",
 "items":[{"code":"603112","decision":"同意","reason":"…"},{"code":"002583","decision":"否决","reason":"…"}],
 "order":["603112","002583","600498","603626","300418"]}
EOF
```
- 如果 Kiro Crew 装在用户本机电脑（不在服务器上），就无法读 /etc/qishi.env：改为请求 `https://q.whynot9527.xyz/api/review`，加 `-u chairman:<看板密码>`，看板密码和录入口令由用户在本机设置成环境变量 `QISHI_DASH_PASS`、`QISHI_TOKEN`，不要写进仓库。读取顺延链也改为下载看板页 `https://q.whynot9527.xyz/` 里内嵌的数据（`const D = {...}` 中 studios[].pending_buy）。
- `items` 只能包含当前顺延链里的代码；`order` 若提供，必须是顺延链全部代码的重排。
- 交易日 14:25 以后接口拒绝写入。
- 每组一次请求；返回 “X组复核已保存” 才算成功。

每组一行，否决的单独列出事实和来源链接。最后一行写“未复核/失败的组及原因”。
